## 2. 데이터 흐름 (수식 체인)

```
result2!A (소재 ID)
  │  =IFERROR(VLOOKUP(A2,'상품 id'!$D:$F,3,FALSE),0)
  ▼
result2!B  ← 쇼핑몰 상품ID
  │  (피벗 새로고침, 날짜 필터 수동 변경)
  ▼
피벗!A:H  ← 상품ID별 노출/클릭/비용/전환 합계
  │  =IFERROR(XLOOKUP($B6,피벗!$A:$A,피벗!$B:$B,0,0),0)  ×8회
  ▼
상품별 데이터!F:O
  ├─ C 노출용 상품명 = XLOOKUP(B, '상품 id'!F:F, '상품 id'!E:E)
  ├─ D 기본 상품명   = VLOOKUP(B, '상품 id'!A:B, 2, 0)
  ├─ E 상품군        = VLOOKUP(D, '상품군 분류'!B:C, 2, 0)
  ├─ H CTR  = G/F
  ├─ I CPC  = J/G
  └─ M 구매완료 ROAS = L/J
  │  =SUMIFS('상품별 데이터'!$F$6:$F$1000, '상품별 데이터'!$E$6:$E$1000, $B6)
  ▼
상품군별 데이터!C:L
  └─ 상품군 CTR/CPC/ROAS 는 합계로 재계산 (D6/C6, G6/D6, I6/G6)
```

## 3. 확인된 문제점

### 3.1 헤더와 실제 값 불일치 (가장 중요)

`result2!B` 열의 헤더는 **"상품번호(스마트스토어)"** 인데, 수식은
`'상품 id'!$D:$F` 의 **3번째 열 = F열 = 쇼핑몰 상품ID** 를 가져옵니다.
즉 헤더 이름과 실제 담긴 값이 다릅니다.

이후 `상품별 데이터!B` 도 이 값을 그대로 받으므로, 시트 전체가
"스마트스토어 상품번호"라는 이름으로 **쇼핑몰 상품ID**를 다루고 있습니다.

→ DB에서는 `products.mall_product_id` 와 `products.smartstore_product_no` 를
**분리된 컬럼**으로 보관합니다. 값이 우연히 같더라도 합치지 않습니다.

### 3.2 상품 id 시트의 A열 성격

`상품 id!A` 는 489행이고, F열(쇼핑몰 상품ID) 고유값 183개 중 **180개가 A열에 존재**합니다.
나머지 3개는 `파워링크`, `쇼핑브랜드형`, `브랜드 검색` — 즉 상품이 아닌 광고 유형입니다.
A열은 사실상 "상품 ID → 기본 상품명" 사전으로 쓰이고 있습니다.

### 3.3 수동 작업 의존

`사용방법` 시트에 적힌 7단계가 전부 손으로 하는 일입니다.

1. RAW 다운로드 → 2. result2 주황 영역에 붙여넣기 → 3. 피벗 날짜 필터 수정 + 새로고침
→ 4. 피벗 A열 복사 → 5. 상품별 데이터 B열 붙여넣기 → 6. C~M열 수식 행 맞추기
→ 7. 브랜드검색·쇼핑브랜드형·파워링크 필터로 제외

행 수가 바뀔 때마다 6번(수식 행 맞추기)을 다시 해야 하고, 빠뜨리면 조용히 틀린 값이 나옵니다.

### 3.4 성능 낭비

`상품별 데이터` 와 `상품군별 데이터` 는 1000행까지 수식이 걸려 있으나 실제 데이터는 60행입니다.
`SUMIFS` 가 매번 빈 행 940개를 훑습니다.

### 3.5 매핑 실패가 눈에 띄지 않음

- 소재값이 `-` 인 행 2건 → B열이 0
- B열이 0인 행 6건
- `사용방법` 마지막 줄에 "0으로 뜰 경우 상품 id 시트에 정보 추가"라고만 적혀 있고,
  누락 사실을 알려주는 장치가 없습니다.

## 5. 검증

엑셀의 소재→상품ID→피벗→상품별 집계 체인을 파이썬으로 재현해
`상품별 데이터` 시트의 **60행 전체가 값까지 정확히 일치**함을 확인했습니다.
이 로직을 그대로 `fn_product_stats` 로 옮겼습니다.

```

```
